\section{Project objective}

The project investigates whether switching characteristics of a memristor device can
be predicted from measurements available earlier in the device's switching
sequence. The first phase studies the same-cycle mapping, where we try to predict the values for the RESET operation based off of given values of the respective SET operation:

\[
X_{\mathrm{SET},n}
\longrightarrow
Y_{\mathrm{RESET},n},
\]

where both vectors contain

\[
[V_{\mathrm{start}},V_{\mathrm{final}},G_{\mathrm{initial}},
G_{\mathrm{final}}].
\]

The second phase is concerned with what happens between the cycles. For the given RESET operation's parameters, we try to predict the SET operation's parameters from the next respective cycle :

\[
X_{\mathrm{RESET},n}
\longrightarrow
Y_{\mathrm{SET},n+1}.
\]

For exploring the possibility of predicting these values as accurately as possible, we use the Linear Regression machine learning model. In the latter stages of the project, we will try to introduce the MLP model, in the hopes of getting more precise data prediction.

\section{Dataset}

The experiments use \texttt{F2s\_7\_0.parquet} file, where the switching characteristics of one device have been recorded. The dataset contains 5695 cycles and 19 extracted switching metrics. Its columns form a Pandas
MultiIndex with separate \texttt{SET} and \texttt{RESET} groups. Each row is indexed by the experimental conditions, device identifier, and cycle number:
\texttt{RESET\_pw}, \texttt{RESET\_target}, \texttt{Device}, and
\texttt{Cycle}.

\section{Data validation and filtering}
Filtering only takes into account the values which are needed for our model. While the recorded data has a total of 19 metrics for each SET and RESET operation combined (so, per cycle), only 8 of those are used. If at least one of the other 11 metrics is \textbf{NaN} (Not a Number), the cycle will not be discarded as those parameters, at the moment, pose no use for us. Only when at least 1 of the 8 used values is affected by the raised \textbf{has\_error} flag or the \textbf{NaN} statement, do we discard the given cycle.

For a given cycle, a row is valid only when all four SET and RESET metrics and both error flags are valid.

\section{Linear regression model}

The used model is a multi-output \texttt{Linear Regression} model from
scikit-learn. Input features are standardized with \texttt{StandardScaler} (this will potentially be useful once we switch to the MLP model later on.
The training inputs are standardized, the learned transformation is
then applied to validation and test inputs.

For a standardized input vector $z$, the model predicts

\[
\hat{y}=Wz+b,
\]

where $W\in\mathbb{R}^{4\times4}$ is the weight matrix and $b\in\mathbb{R}^{4\times1}$ is the bias matrix. Each target has
its own linear combination of the four inputs, since we have 4 outputs. The four output equations are
mathematically independent, although scikit-learn fits them through one
multi-output model call.

Error evaluation is done for each of the four target values that we are trying to predict . The metrics used during the project are mean absolute error (MAE), mean squared error (MSE), root mean
squared error (RMSE), and the coefficient of determination $R^2$ .

\subsection{Conclusion of the experiments}

After carefully considering the given problem from a purely mathematical point of view, we have come to a conclusion - the model that was trained on chronological data and the model that was trained on randomly-sampled data do not differ. For ordinary linear regression, the order in which the training data is fed into the model does not matter -  as long as the elements of the training data set are identical. Let's take a look at the proof for why that is. Let $P$ be a permutation matrix that only changes row order:

\[
X'=PX,
\qquad
Y'=PY.
\]

Because of the identity $P^TP=I$, further we have:

\[
X'^TX'=X^TP^TPX=X^TX
\]

and

\[
X'^TY'=X^TP^TPY=X^TY.
\]

The normal equations, weights and biases therefore must remain the same. Consequently, the difference in the evaluation results between the two experiments arises in the fact that the training, validation and test data is not the same. Since we randomly shuffled the switching cycle data, the elements in the respective sets between the experiments are different, therefore we get, at first glance, different results.

\section{Phase II: previous-cycle RESET to next-cycle SET prediction}

The next question in the project that naturally arises is this: given the parameters of a RESET operation, can we predict the values of the SET operation of the next cycle? In other words, given the RESET characteristics of cycle $n$, can we predict the SET characteristics of cycle $n+1$ ?

\[
\begin{bmatrix}
V_{\mathrm{start}}\\
V_{\mathrm{final}}\\
G_{\mathrm{initial}}\\
G_{\mathrm{final}}
\end{bmatrix}_{\mathrm{RESET},n}
\longrightarrow
\begin{bmatrix}
V_{\mathrm{start}}\\
V_{\mathrm{final}}\\
G_{\mathrm{initial}}\\
G_{\mathrm{final}}
\end{bmatrix}_{\mathrm{SET},n+1}.
\]

\subsection{Data manipulaton}

In order to properly load the data into the model, the RESET characteristics used for prediction need to be assigned to the SET characteristics of the next given cycle. To accomplish that, we shift the columns that contain the RESET data, down by one row. That way, the RESET data from cycle $n$ is paired with the SET data from cycle $n+1$ . Also it is worth noting that, since we have shifted all the data down by one row, that one cycle will now be rendered obsolete, as the first SET will no longer have a corresponding value for the RESET characteristic, and the last RESET will not have a corresponding  SET characteristic.

To verify that the shift was performed correctly, the RESET->SET pairs
were independently reconstructed row by row without using
\texttt{groupby(...).shift(1)}. Both methods produced identical $X$ and
$Y$ datasets. Of the 5694 consecutive candidate pairs, 14 were excluded
because of NaN values and none because of error flags, leaving 5680 valid
pairs. The test subset begins with
$\mathrm{RESET}_{5126}\rightarrow\mathrm{SET}_{5127}$ and ends with
$\mathrm{RESET}_{5693}\rightarrow\mathrm{SET}_{5694}$.

\subsection{Test results}

Relative MAE is defined as

\[
\mathrm{relative\ MAE}\,[\%]
=100\frac{\mathrm{MAE}}{\operatorname{mean}(|y_{\mathrm{true}}|)}.
\]

This quantity describes how large the average error is, compared to the mean of the true target values, in percentage. If the relative MAE was, let's say, 100\%, that would mean that the average error of our predicted values is equal to the magnitude of the mean of the true target values. In essence, the prediction errors would be of the same scale as the values we are trying to predict, indicating a very poor result.

\section{Learned augmented parameter matrices - the math behind the curtain}

In order to understand what truly lies behind the models which we are using, we will have to go over some basic linear algebra. Assume that the training set contains $n$ examples (cycles). The four input parameters of all the examples are arranged into the matrix

\[
X=
\begin{bmatrix}
x_{11} & x_{12} & x_{13} & x_{14} \\
x_{21} & x_{22} & x_{23} & x_{24} \\
\vdots & \vdots & \vdots & \vdots \\
x_{n1} & x_{n2} & x_{n3} & x_{n4}
\end{bmatrix}
\in\mathbb{R}^{n\times4}.
\]

Each row represents one training example, while the four columns represent \texttt{start\_v}, \texttt{final\_v}, \texttt{initial\_g}, and \texttt{final\_g}. The corresponding target values are arranged in a matrix of the same dimensions

\[
Y=
\begin{bmatrix}
y_{11} & y_{12} & y_{13} & y_{14} \\
y_{21} & y_{22} & y_{23} & y_{24} \\
\vdots & \vdots & \vdots & \vdots \\
y_{n1} & y_{n2} & y_{n3} & y_{n4}
\end{bmatrix}
\in\mathbb{R}^{n\times4}.
\]

To include the bias terms in the same matrix multiplication, a column of ones is added to $X$:

\[
\widetilde{X}=
\begin{bmatrix}
1 & x_{11} & x_{12} & x_{13} & x_{14} \\
1 & x_{21} & x_{22} & x_{23} & x_{24} \\
\vdots & \vdots & \vdots & \vdots & \vdots \\
1 & x_{n1} & x_{n2} & x_{n3} & x_{n4}
\end{bmatrix}
\in\mathbb{R}^{n\times5}.
\]

We do this trick in order to contain all the parameters of interests - the weights and the biases, into a single matrix \textit{B}. Therefore the \textit{B} matrix and the predictions for all $n$ examples can be written as

\[
\widehat{Y}=\widetilde{X}B,
\qquad B\in\mathbb{R}^{5\times4}.
\]

The matrix dimensions show how the complete prediction matrix is produced:

\[
\underbrace{\widetilde{X}}_{n\times5}
\underbrace{B}_{5\times4}
=
\underbrace{\widehat{Y}}_{n\times4}.\]
The matrix \textit{B} is as follows:
\[
B=
\begin{bmatrix}
b_1 & b_2 & b_3 & b_4 \\
w_{11} & w_{12} & w_{13} & w_{14} \\
w_{21} & w_{22} & w_{23} & w_{24} \\
w_{31} & w_{32} & w_{33} & w_{34} \\
w_{41} & w_{42} & w_{43} & w_{44}
\end{bmatrix}
\in\mathbb{R}^{5\times4}.
\]

The first row of $B$ contains the four biases for the respective four equations that the equation above produces. The remaining rows contain the weights of the four inputs and the columns correspond to the
four predicted target quantities. Internally, the code standardizes every input column according to $z_{ik}=(x_{ik}-\mu_k)/\sigma_k$, forming the standardized input matrix $Z\in\mathbb{R}^{n\times4}$. After adding the bias column, the same predictions can be written as $\widehat{Y}=\widetilde{Z}B_z$. The matrices $B$ and $B_z$ therefore represent the same linear regression model in two different input coordinate systems: $B$ operates on the original input matrix $X$, whereas $B_z$ operates on the standardized input matrix $Z$. Standardization centres each input column around zero and scales it to unit standard deviation, which is important because volts and siemens differ by orders of magnitude. In both cases, the predicted target values remain in their original physical units.

If the weight matrix is written with targets as rows and inputs as columns, the two
representations satisfy

\[W=W_z\operatorname{diag}(\sigma^{-1}),\qquad
b=b_z-W\mu.
\]

The magnitudes in different target columns must not be compared directly, because voltage and conductance targets use different physical units. The tables retain scientific notation instead of rescaling the physical data.
